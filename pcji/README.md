# PCJI — Proactive Customer Journey Intelligence (Demo Prototype)

An interactive banking CX intelligence demo built from the PCJI project brief:
detects friction across customer journeys, scores customer health, predicts
disengagement, and recommends/tracks proactive interventions.

## What's real vs. simulated
- **Fully functional**: all 6 modules, the friction-detection rule engine, health
  scoring, alerting, and the case-management workflow run live against the
  generated dataset — nothing here is a static mockup.
- **Simulated data**: all 25,000 customers, transactions, complaints, etc. are
  synthetic (generated by `data_generator.py`), fictional, and not drawn from
  any real bank or real people.
- **Illustrative predictions**: health scores, risk categories and the
  Predictive Intelligence module are rule-based heuristics for demonstration —
  not validated machine-learning outputs (the app also says this on-screen).
- **Future production integration**: a real build would connect core banking,
  CRM, contact-centre and VOC systems in place of the synthetic layer, and
  swap SQLite for PostgreSQL — the schema is plain relational SQL throughout,
  so that swap is mechanical, not a rewrite.

## Run it
```bash
pip install -r requirements.txt
python data_generator.py      # builds data/pcji.db (~75MB) — run once
streamlit run app.py
```
Then open the local URL Streamlit prints (usually http://localhost:8501).

## Dataset scale (matches the brief)
25,000 customers · 121,574 transactions · 327,803 unified journey events ·
10,679 complaints/service requests · 19,686 feedback (CSAT/NPS/CES) records ·
107,896 onboarding events · 81,435 digital interaction records.

## Modules
1. **Executive Intelligence Overview** — KPIs, health distribution, trends, value at risk
2. **Customer Journey Intelligence** — onboarding funnel, stage drilldowns, friction by stage
3. **Proactive Friction Detection** — alert centre with filters + case actions (approve/escalate/resolve/reassign)
4. **Predictive Intelligence** — dormancy, onboarding-abandonment, repeat-complaint & SLA-breach risk lists
5. **Customer 360 & Journey Reconstruction** — pick any customer, see their full timeline and risk profile
6. **Intervention & Service Recovery** — case queue, outcome tracking, and a scripted live demo
   scenario for Customer CUS-000001 (repeated transfer failures → delayed reversal → complaint →
   declining activity → detection → simulated recovery). Use the **Simulate New Friction Event**
   button here to inject a live failure and watch the alert centre react.

## Tech stack
Python, Streamlit, Pandas, Plotly, SQLite (stand-in for PostgreSQL). scikit-learn
is included in requirements for a future validated predictive-model phase.

## Project structure
```
app.py                 # entry point / navigation
data_generator.py      # synthetic dataset generator (run once)
modules/
  data_access.py       # SQLite loaders (cached)
  engine.py             # friction detection + health scoring + alert rules
  style.py              # brand colors, CSS, chart theme, KPI/badge helpers
  m1_executive.py .. m6_intervention.py   # the six application modules
data/pcji.db            # generated SQLite database (created by data_generator.py)
```
